Loom / Engineering onboarding

Six weeks to shipping

A dependency-ordered path through loomcli and fleet-db, built for an engineer who is fluent in Go and new to this system. Every lesson ends with something you run against the real repos.

Track full-stack, backend-first Shape 15-40 min lessons, part-time Pinned to loomcli ce4df56fb · fleet-db 000793b
How to use this

Read in order — the sequence is by dependency, not by repo, so each lesson assumes only what came before it. Do the exercises; they are where the learning actually happens. Keep the two reference cards open in tabs. And when something here disagrees with the code, the code wins — tell your teacher so the lesson gets fixed.

The reference shelf

These four are the documents you will come back to long after the lessons are done. Print them.

The Loom Glossary The trap words — ordinary English used as precise domain terms, and the mechanism behind each. Finding Anything Where the code for a thing lives, the layering rules, and the patterns you are expected to copy. fleet-db Data Model The key schema, what is authoritative versus derived, the event shape, and the Lua scripts. First-Task Workflow Claim to pull request, in either repo, with every shared-machine safety rule inline.
Week 1

Orientation and environment

By Friday you can find the code behind any command, use the vocabulary precisely, run a full local stack without disturbing a colleague, read the gate as the team's coding standard, and place any piece of state in the tier that owns it.  ·  5 lessons, about 2.4 hours

  1. 01 Two repos, one system Locate the code behind any CLI command, in under two minutes. 25 min
  2. 02 The words that lie Disambiguate this codebase's overloaded terms — and notice when someone else has not. 25 min
  3. 03 Run it without breaking anyone Stand up a local stack that is provably yours, on a shared machine. 35 min
  4. 04 The gate is the spec Read make gate as the team's executable style guide. 30 min
  5. 05 Where state lives Name every core object and say which of three storage tiers holds it. 30 min
Week 2

The spine

By Friday you can trace any command from a shell argument to an HTTP write and back, and know which of the two client stacks you are standing in before you touch an error.  ·  2 lessons, about 1.2 hours

  1. 06 Anatomy of a command Follow one command through all eleven hops — the trace every later lesson attaches to. 40 min
  2. 07 Two clients, one server Pick the right client stack and the right error model for a change. 30 min
Week 3

The runtime

By Friday you can explain how many agents share one queue with no coordinator, predict where a task lands when its run dies, and say what is actually isolated from what.  ·  4 lessons, about 2.2 hours

  1. 08 Claiming without collisions Explain — across both repos — why two agents never take the same task. 35 min
  2. 09 When a run dies Predict where a task ends up when its agent crashes, hangs, or lies. 40 min
  3. 10 What actually runs your code Answer the first question of every incident: where is this running? 30 min
  4. 11 Things that are not boundaries Tell an OS boundary from an admission check, a flag, and a sentence in a prompt. 30 min
Week 4

The web layer, and what proves it

By Friday you can add an endpoint that follows the layering, decide from the code alone whether a stream is resumable, change the frontend safely, carry a field from schema to pixel — and then state honestly what your tests proved.  ·  6 lessons, about 3.5 hours

  1. 12 How serve is put together Add an API endpoint without asking anyone where things go. 35 min
  2. 13 Realtime, one frame at a time Answer “is this stream resumable?” by reading the handler. 35 min
  3. 14 The React app Change a quarter-million lines of TypeScript safely, on four rules. 35 min
  4. 15 Shipping a vertical slice Take one field from a line of YAML to a rendered pixel. 40 min
  5. 16 What proves what Choose the cheapest test tier that settles your question, then claim only what it earned. 35 min
  6. 17 The edges Place the four directories that are neither the CLI, the web layer, nor fleet-db. 30 min
Week 5

The other repo

By Friday you can work inside fleet-db: say what is authoritative and what is derived, find any state in Redis, read the API contract you have been calling all along, and know what your deployment's history guarantee actually is.  ·  7 lessons, about 4.0 hours

  1. 18 The event log is the truth Say whether any piece of fleet-db state is authoritative or derived. 35 min
  2. 19 Rebuilding the world Predict exactly what a replay restores, and what it silently does not. 35 min
  3. 20 Where atomicity lives Decide when an operation needs a Lua script, and find any key in the schema. 35 min
  4. 21 The API you already depend on Find the endpoint behind any store call, and read its contract first. 30 min
  5. 22 Auth at the boundary Say what authenticates and what authorizes, in each mode — and what dev mode is not. 30 min
  6. 23 Keeping the log honest Answer “how much history do I have?” and never trim past the fence. 40 min
  7. 24 When Redis dies Choose a recovery path, and state what it destroys before running it. 35 min
Week 6

Across both repos, and shipping

By Friday you can reason about ownership and configuration in the control plane, reconstruct what an agent did after the fact, sequence a change that spans both repos, and take a real task from claim to open pull request without help.  ·  7 lessons, about 4.3 hours

  1. 25 Who owns this agent Determine who owns an agent now — including the third answer, inconclusive. 35 min
  2. 26 Roles, skills, and shaping work Configure a role so the right agent claims the right task. 30 min
  3. 27 Seeing what happened Reconstruct what an agent did from the artifacts it left behind. 35 min
  4. 28 One change, two repos Sequence a cross-repo change so neither side is ever broken. 40 min
  5. 29 fleet-db builds itself Pass the other repo's gate, and read its policy file as its constitution. 35 min
  6. 30 When the docs are wrong Verify a documentation claim against code before you act on it. 25 min
  7. 31 Your first task Claim, build, prove, and open a pull request — then know where to go next. 60 min
