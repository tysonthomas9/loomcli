# Selected history recovery ownership

The optional selected-history read now travels through the captured Fleet backend, backend subscriber, bound source, recovery registry and Loom HTTP route. It never resolves a fresh backend by workspace. Selected and unselected requests share the handle's single-flight slot, principal/workspace authorization, deadline, shutdown and durable source checks. Repeated requests may select a different issue, but every response must echo its own scope. Source replacement still permanently retires the bound source.

The Loom route accepts one optional issue_id query value, subject to the same nonblank Go whitespace, valid UTF-8 and 1024-byte limit as Fleet. Unknown/duplicate/malformed queries, bodies and repository scope are rejected. Missing selected capabilities fail without falling back to ordinary reads. Selection metadata is checked against the actual raw document at both bound-source and registry boundaries. The scope checker rejects duplicate JSON keys, trailing data, oversized documents and excessive nesting; it supplements Fleet's complete native validator rather than replacing it.

On the browser side, committed useIssueHistory hooks register their exact workspace/issue ownership with the EventProvider's selection registry. Mounted hidden panels participate while enabled. Detail revisions do not create a new selection generation; changes to issue, workspace, enabled state or registration membership do. Duplicate owners of one issue can share a selected window. Conflicting issue scopes fail the suspended recovery attempt instead of choosing one or silently dropping coverage. Speculative suspended renders do not register a new selection.

A resync suspends the exact transport, then captures one immutable selection lease. The HTTP reader forwards that issue and prepares only a matching native response. The attempt listens to transport and selection cancellation, checks both around observer callbacks, discards prepared data on revocation, and releases incoming leases even when admission fails reentrantly. Any committed A-to-B-to-A change invalidates the original attempt. A late response that ignores abort cannot restore it. Failed attempts retain failure status until retirement; selection changes never automatically resume SSE. Explicit retry still starts from the prior accepted checkpoint.

No timeline adapter, UI cache publication, all-view coverage certificate or checkpoint acknowledgment is added. A prepared selected history remains private to its attempt. The next phase must publish one owned generation across all required stores and ordinary/optimistic writers before accepting through.
