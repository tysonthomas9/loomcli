1. **Blocker, Decisions 1/3/4: run/invocation columns do not have a reliable data source yet.**  
   `AgentSession` currently has `Attempt`, but no first-class `task_run_id` or `invocation_key` field ([internal/domain/control_plane.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/domain/control_plane.go:90)). The store create/filter types also lack those fields, so Traces cannot server-filter by `task_run_id` today ([internal/store/control_plane_store.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/store/control_plane_store.go:48), [internal/store/control_plane_store.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/store/control_plane_store.go:64)). Existing flue sessions only stamp `task_run_id` into metadata and use legacy ids like `flue-<taskRunID>` ([internal/driver/task_bridge_session.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/driver/task_bridge_session.go:294), [internal/driver/task_bridge_session.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/driver/task_bridge_session.go:302)).  
   **Recommendation:** make `task_run_id`, `invocation_key`, and display attempt explicit API fields; use metadata fallback for legacy rows; do not parse ids except as a last-ditch legacy fallback.

2. **Blocker, Decision 5: judge linkage is not implementable from current eval/session APIs.**  
   `SessionEval` has no `judge_session_id` ([internal/domain/session_eval.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/domain/session_eval.go:32)), `SessionEvalState` only returns status/request/eval ([internal/webui/service/evals.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/webui/service/evals.go:80)), and session detail responses do not expose arbitrary metadata where `judged_session_id` could be read ([internal/webui/server/dto/session_response.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/webui/server/dto/session_response.go:9)). Today’s built-in eval judge shells out to `codex` inside a task runner, stores only runtime metadata/result, and does not create a judge `AgentSession` transcript ([internal/workflows/builtin/session-eval-task-runner.ts](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/workflows/builtin/session-eval-task-runner.ts:75), [internal/workflows/builtin/session-eval-task-runner.ts](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/workflows/builtin/session-eval-task-runner.ts:100)).  
   **Recommendation:** add `judge_session_id` to the eval write payload/domain/API, ensure the judge process really creates an `AgentSession kind=judge`, and expose `judged_session_id` as an explicit detail field, not raw metadata scraping.

   **Recommendation:** for `kind=judge`, disable/hide re-judge and render judge-specific linkage instead.

   **Recommendation:** add the nested route, active-view tests, and a run-view endpoint that returns `{task_run, sessions, missing_task_run}` or equivalent.

7. **Should-fix, Decision 4: header totals are ambiguous.**  
   `TaskRun` has status, token fields, and timing fields, but no file-change stats ([internal/domain/platform.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/domain/platform.go:498)). 8. **Should-fix, Decisions 1/4: run table ordering and legacy attempt display need exact rules.**  
   Current workspace sessions are sorted newest-first by `StartedAt` ([internal/infra/memstore/control_plane.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/infra/memstore/control_plane.go:223)), while the run view says “attempt then start time” without direction or tie-break. Current response names the field `attempt_num`, not `attempt` ([api/openapi.yaml](/Users/tyson/codebase/code-agents/agent-traces/loomcli/api/openapi.yaml:6519)).  
   **Recommendation:** define `attempt ASC, started_at ASC, invocation_key ASC, session_id ASC`; define legacy zero/missing attempt display.

9. **Should-fix, Decision 5: re-judge race semantics are not defined.**  
   Rejudge deletes the old eval record for the stamped prompt version, clears eval metadata, and marks `eval_requested=true` ([internal/evals/evals.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/evals/evals.go:379), [internal/evals/evals.go](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/evals/evals.go:385)).    **Recommendation:** say whether the old eval/judge transcript remains visible as stale, disappears, or is replaced only when the new eval lands. Prefer joining strictly from the displayed eval record’s `judge_session_id`.

10. **Nit, Decision 3: URL naming should be pinned.**  
   Current Traces URL/API params use snake_case such as `agent_id` and `kind` ([internal/webui/frontend/src/api/terminal/workspaceSessions.ts](/Users/tyson/codebase/code-agents/agent-traces/loomcli/internal/webui/frontend/src/api/terminal/workspaceSessions.ts:40)).  
   **Recommendation:** use `task_run_id` consistently for the list filter URL param and API query param, and make the run-view chip clear back to `/traces?task_run_id=...` or plain `/traces` explicitly.
